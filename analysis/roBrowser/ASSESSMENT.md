## Executive Summary

roBrowser is a browser-based Ragnarok Online client. It is written in modern ES modules, rendered with WebGL, built with Vite 8 on Node 22, and ships as Web, PWA and Electron builds. It has about **373K non-blank lines of first-party JS**, but only about **148K of those are hand-written logic**. The other ~225K are generated packet-length tables and static game-data tables. The stack is current and the UI migration to Shadow-DOM `GUIComponent` is complete, so the platform is **not** legacy. The real risks are **security** and **coupling**:

- **Security.** The Electron build gives Web Workers full Node.js access. Combined with HTML-injection sinks in NPC dialog and mail, that makes stored XSS → RCE on players' machines possible. `wsproxy.js` is an open TCP relay.
- **Coupling.** Cycles run between domains (Engine↔UI, DB↔Renderer).

**Headline recommendation: Refactor in place, security first.** A greenfield rebuild would throw away a working, actively maintained client to fix problems that targeted changes can fix.

## Technical Debt (top 10, ranked by remediation value)

1. **wsProxy is an open TCP relay.** `wsproxy.js:42,52-62` connects to any `host:port` taken from the URL path. There is no allowlist, Origin check or rate limiting, and `parseInt` is not checked for NaN. (Also listed as SEC-002.)
2. **Synchronous XHR on the main thread.** `src/Core/FileManager.js:183` calls `req.open('POST', …, false)` with no status or error handling. `src` has 8 `XMLHttpRequest` calls against 3 `fetch`.
3. **Generated packet-length code dominates the codebase.** `src/Network/Packets/` has 23 files and about 144K non-blank lines. `packets2008_len_main.js` alone has ~17.9K `if (packetver >= …)` branches. These should be a data table plus one resolver; that removes bundle and parse cost.
4. **God modules.**
   - `PacketStructure.js` (14.3K LOC) has 417 `prototype.build` assignments and 6 `writeULong(0) // TODO … UINT64` sites (`:12281-12369`), which may truncate 64-bit fields.
   - `DBManager.js` has 1,531 decision points and 11 TODOs.
   - `MapEngine/Entity.js` is 2.7K LOC.
5. **Legacy singleton and prototype patterns.** 920 `X.method = function` lines in 124 files, and 548 `.prototype.x =` lines in 11 files. These conflict with AGENTS.md's "Modernize on Touch".
6. **Global drag state copied 16 times.** `window._OBJ_DRAG_` has 40 references; examples are `InventoryCommon.js:1259`, `Guild.js:1993`, `NpcStore.js:1205` and `UI/TouchDrag.js:85`. It should be one `UI/DragState.js` module.
7. **Webserver URL and XHR block duplicated, with a plain-HTTP default.** The block appears at `Guild.js:229,594` and `ShortCut.js:1187,1218` with a hardcoded `http://127.0.0.1:8888`. `Guild.js` sends `Session.WebToken` over that connection.
8. **Import cycles masked by dynamic `import()` without `.catch`.** There are 27 such dynamic imports, for example `NetworkManager.js:368`, `UIManager.js:211` and `Camera.js:296` (4 in that file). Across scope there are 46 `.then` calls against 13 `.catch`.
9. **`var` and deprecated APIs.** 408 `var` in 127 `src` files, which goes against the `no-var: error` lint rule. There are also 59 `substr` calls and `document.execCommand` in `ChatBox.js:346`.
10. **Dead code, broken wiring and doc drift.**
    - **Broken import:** `UI/Components/WinPrompt/WinPrompt.js:13` imports `UI/Components/WinPopup.js`, which does not exist.
    - **Never imported:** `Utils/CRC32.js` (so its prototype patch never runs), `Utils/HTMLEntity.js`, `Utils/partyColors.js`, `Renderer/Effects/MagnumBreak.js`, `Renderer/Effects/GroundEffect.js`, `UI/Components/Error/Error.js`, `DB/Jobs/JobPropertyTable.js`.
    - **Wrong build targets:** `npm run build:grfviewer` passes `-G`, which builds **GrannyModelViewer** (`builder-web.mjs:62`). `build:ai` passes `-A`, which matches no builder module. `build:vite` points at a root `index.html` that doesn't exist.
    - **Dead branch:** a legacy jQuery `UIComponent` branch remains at `GUIComponent.js:576-577`.
    - **Other:** 99 TODOs and ~120 lines of commented-out code.

## Documentation Gaps (top 5)

1. **Where the packet tables come from.** Nothing says whether `src/Network/Packets/*_len_main.js` is regenerated from Hercules/rAthena or hand-edited, or how to regenerate it. This decides whether item 3 can be automated.
2. **Security and deployment model.**
   - The docs don't say whether wsProxy is meant to be public, or what the Electron trust boundary is (why workers need Node: `FileManager` and `GameFile` use `require`).
   - `postMessage` embedding contract: no doc says which origins may configure the client.
3. **Builder and entry-point map.**
   - The `-G/-D/-A` flag semantics are undocumented and the npm scripts disagree with them.
   - Nothing says that `src/main.js` is used only by the api and electron hosts, not by the production web build.
4. **The Lua/DB loading pipeline.** How `DBManager` picks and loads `.lub` tables per PACKETVER through wasmoon, and the fact that `DB/Effects/EffectTable.js` is executable code wired to Renderer classes.
5. **Cross-module contracts that grep can't see.**
   - The `window._OBJ_DRAG_` drag protocol between 17 files.
   - `SessionStorage` as shared mutable state.
   - The dynamic-`import()` convention used to dodge cycles.
   - AGENTS.md has drifted from the code: `FileManager` is already a static class, and the TODO counts differ.

## Recommended Modernization Pattern

**Refactor (in place, incremental). Routes to `/modernize-harden` first, then `/modernize-transform` for targeted modules.**

roBrowser is already on a current stack:

- ES modules, Vite 8, Node 22 and Electron 41.
- An active commit history, a completed UI migration, 90 test files, and CI with lint, format and CodeQL.

Neither Rehost/Replatform nor a same-stack version uplift applies, because nothing is behind a version. **Rebuild (`/modernize-reimagine`) is not recommended for the client as a whole.** The value is in about 148K lines of hard-won protocol and rendering behaviour across 23 PACKETVER generations, and the problems found are local, not structural failures of the platform. The order with the best value per effort is:

1. **`/modernize-harden`** for SEC-001…SEC-007 and SEC-015. Turn off Node in Electron workers and move file I/O behind IPC. Add escape-by-default for NpcBox, Mail, Rodex and `getItemName`. Put an allowlist and Origin check on wsProxy, and an origin allowlist on the embed API.
2. **`/modernize-transform`** on bounded modules:
   - Convert `Network/Packets/*` from generated code into a data table plus a resolver.
   - Split `PacketStructure.js` by family and `DBManager.js` by domain.
   - Replace `window._OBJ_DRAG_` and the duplicated webserver XHR with modules.
   - Break the Engine↔UI and DB↔Renderer cycles with event injection.
3. **Hygiene:** commit a lockfile, fix the `build:grfviewer`/`build:ai` scripts and the `WinPrompt` import, delete confirmed-dead modules, and refresh AGENTS.md.

If a **reimagine** is still wanted, scope it to a self-contained piece: a hardened **wsProxy gateway** (allowlist, auth, wss termination, rate limiting), or a **declarative packet-schema layer** generated from rAthena/Hercules definitions. Both have clear contracts and low blast radius.
